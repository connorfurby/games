# Grocery Empire 2.0 — plan

Full audit and rationale: https://claude.ai/artifact/DgAJbqsxSb6RBq8FTd7uGW

## Thesis

Each era multiplies income ~1,000×, and the store you started with stays the engine.
Every purchase visibly changes the store. Every upgrade/perk is worth ≥ ×1.25 on something, or a new verb.

## Phases (each closed by a gate)

| Phase | Scope | Gate |
| --- | --- | --- |
| 0 Stabilize | Bug fixes, CI, pacing test, self-hosted fonts | Build + tests green in CI |
| 1 Foundation | Selector subscriptions, throttled suggestions, one upgrade-effect path | Tests + bots pass |
| 2 Economy | Multiplicative income, store engines, era multipliers, savings goal, payback hints | Greedy bot hits era targets |
| 3 UI | Design system, 5 hubs, store scene, next-goal bar, inbox drawer, upgrade graph, mobile | Playable at 390 px |
| 4 Content | ~360 upgrade nodes / 10 trees, milestones every 5 ranks, tree mastery, Empire rewards, constellation, projects | No node under ×1.25 |
| 5 Length | Rebrand + Relocate prestige, named rivals, offline newspaper | Long-run bot completes |

## Decision log

- **Numbers stay `number` in the sim.** Doubles are exact to 9e15 and represent values to 1e308; the 2.0 curve tops out near 1e15/s before prestige. `break_eternity.js` stays for display formatting. Revisit only if a prestige layer needs > 1e300.
- **Evolve the sim, rebuild the UI.** Commands, migrations, invariants and bots are kept; UI is rebuilt hub by hub.
